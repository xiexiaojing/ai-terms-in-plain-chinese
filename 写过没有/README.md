# 写过没有

一个本机跑的独立 web 系统：把 2018 年至今**已发布**的公众号文章和漫画向量化，按**意思**搜——
「这个观点我以前写过吗」，搜到了一键把链接复制走，还能让它结合原文回答一句、并附上出处。
当前 660 篇文章 + 56 篇漫画，篇篇能点开原文。

**这个库要发给学员做 demo**，所以只收已发布的：未发布草稿、没有公众号链接的存稿一律不进索引，
本地路径、发布记录、核稿清单（`fact_notes`）、置顶评论策略这些内部内容也在清洗阶段整段丢掉。
改语料范围之前先想一下这条。

## 三分钟跑起来

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt     # 只有 numpy + httpx，半分钟
cp .env.example .env                          # 填上 LLM_API_KEY
./daemon.sh start                             # http://127.0.0.1:7788
```

依赖只有两个包，本机不跑模型、不下权重。

**不绑定任何一家模型服务**：向量化认 OpenAI 兼容协议（`input` / `data[].embedding`）和 MiniMax 私有协议
（`texts` + `type=db|query` / `vectors`），不填 `EMBEDDING_PROTOCOL` 就自动探测；回答走标准
`/chat/completions`。OpenAI、通义、智谱、硅基流动、本地 Ollama 或 vLLM 自建，改 `.env` 里三行就能接，
样例都在 `.env.example`。一个 key 管检索和回答两头。

⚠️ **换了向量模型必须 `./refresh.sh` 重建索引**——维度和向量空间都变了，不重建的话查询跟库里的向量
根本不在一个空间，检索会安静地全乱、不报错。服务启动时会核对索引里记的模型，对不上直接在日志里说。

**没配 key 也能开**，检索会退成纯 BM25 字面匹配（搜得到，但不懂同义改写），页面上会写明怎么配。

## 它索引了什么

| 来源 | 内容 |
| --- | --- |
| `wechat-article/已归档/*/article.md` | 已发布文章的本地全文 |
| `feishu-claude-bot/data/gzh-history/all-articles.json` | 线上全量档案（2026-08-18 建，631 篇，篇篇带 mp 链接） |
| `feishu-claude-bot/data/gzh/*.json` | 每日快照，用来补建档之后新发的文章 |
| `wechat-comic/{已归档,制作中}/*/` | 漫画：摘要 + 分镜表的台词与图内文字（发过的才进） |

**`wechat-comic/禁止外发/` 有意不扫**。那三篇含真实小区名、社工电话、中标单位，目录 README 写死「一律不发布」；
这系统的按钮是「一键复制走」，不该把它们放进这条流水线。要查那三篇，直接去目录里翻。

本地正文和线上链接靠标题对齐。**发布标题是真相**——本地目录名和候选标题只当别名，
匹配上了就用线上标题显示，免得复制出去的书名号跟公众号里的对不上。

标题对不上时会做一次近似匹配，但要过三关（相似度 ≥ 0.86、和第二名拉开差距、或线上摘要开头
确实出现在本地正文里）。「三言丨…」那类标题成批雷同，只看相似度必然配错；
宁可留空也不配错，引用到别人那篇比没有链接更糟。

## 搜索怎么工作

两路并行，融合后按文章聚合：

- **语义路**：当前索引用接口向量（默认 MiniMax `embo-01`，1536 维）。负责「换个说法也能搜到」——搜「缓存救不了性能问题」能找到《我让 AI 优化性能，它张口就是加缓存》。想完全离线见 `.env.example` 里的本机 BGE 选项。
- **字面路**：中文 bigram BM25。负责「术语必须命中」——搜「达梦 -6105」不能被语义带偏。

文章按 350 字左右分块（块内保留所在小节标题作上下文），一篇里多处命中会加分，
标题命中额外加分。命中片段在结果里高亮，可以直接展开全文确认。

**漫画的文本只取台词**：摘要位 + 分镜表的「文案 / 图内文字 / 背景」列，画面描述截到 60 字跟在后面，
画风指令和人物设定（引用块里那些）整块丢掉。混着排的话，「静姐站立交桥下双手不拿手机」这类描述
会把观点冲淡——实测搜「杀猪盘怎么套人」，画过那篇也只有 0.57，低到被判成「没写过」。

## 刷新

写了新文章、或者 `feishu-claude-bot` 抓了新快照之后：

```bash
./refresh.sh          # 重扫语料 + 重建向量（4000 多块，一两分钟）
./daemon.sh restart   # 服务重启后才生效
```

## 已知边界

- 建索引时去掉了 37 篇没有公众号链接的：未发布草稿、15 篇书章首漫画（本来就不发公众号）、
  以及线上档案里还没抓到的几篇。后者等 `gzh_stats.py fetch` 刷新档案后再 `./refresh.sh` 就会进来。
- 37 篇只有标题和摘要（线上有、本机没存正文），搜得到、点得开，但搜不到正文里的细节，
  也没有「展开全文」。
- 服务默认只监听 `127.0.0.1`。要让学员从局域网访问：

  ```bash
  HOST=0.0.0.0 PORT=7788 ./daemon.sh start
  ```

  开之前想清楚：同一个网络里的人都能打开，没有口令。演示完 `./daemon.sh stop`。


## 问答（RAG 的最后一步）

输入框默认走「问一句」：检索命中的片段喂给模型，用她本人的观点和口吻回答，每句话末尾标 `[n]`，
点角标跳到对应那篇。「只列文章」是纯检索，不调模型。

两条硬约束都是冲着「别编」去的：

- **分数不够就不调模型**。低于 0.52 直接回「这个话题我没写过」，连模型都不叫。这个库的阈值是用
  16 个写过 + 10 个没写过标定出来的，「没写过」是个敢下的结论——让模型对着一堆沾边的片段硬凑，
  才是 RAG 最常见的翻车方式。
- **喂进去的只有命中块**，不是文章开头。命中常在中部，喂开头等于让模型对着不相关的段落答题。

生成走 **MiniMax**（OpenAI 兼容接口）。把 key 填好再起服务：

```bash
cp .env.example .env   # 然后把 LLM_API_KEY 填进去
./daemon.sh restart
```

`.env` 不进 git。默认 `MiniMax-M2.7-highspeed`，端点 `https://api.minimaxi.com/v1`；
换模型或端点写进 `.env` 的 `LLM_MODEL` / `LLM_BASE_URL`。

本机的 `HTTPS_PROXY` 指着翻墙代理，MiniMax 是国内服务，**默认不走代理**（`trust_env=False`）。
真要走加 `MINIMAX_USE_PROXY=1`。

检索仍然全在本机，**生成这一步会把命中的片段发给 MiniMax**——这是接生成之后失去的东西，
演示前值得跟学员说明。
