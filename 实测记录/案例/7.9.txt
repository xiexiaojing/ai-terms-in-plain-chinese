### 规划 planning：模型自己把任务拆成几步

Agent 接到的常常只是一句目标，比如“把这篇文章改成十二格漫画”。从这句话到第一个动作，中间得先想清楚分几步、先做哪一步，这件事叫规划。当时在 OpenAI 的研究员翁荔（Lilian Weng）2023 年写过一篇被引用得很多的文章，把 Agent 拆成四样：大模型，加上规划、记忆、工具使用。后两样这一章各有一节，规划排在最前面。

### 规划可以一次列出，也可以随结果调整

一种是先规划后执行：开头把步骤全列出来，然后照着走，英文叫 Plan-and-Execute。一种是边想边做：干完这一步、看了结果再定下一步，这一种有自己的名字，叫 ReAct。前一种便宜、看着清楚；后一种贵，但能根据刚才的结果改主意。多数产品两种混着来：先拆个大概，中间允许改。

### 步骤看似合理，也可能漏掉关键要求

那串步骤就是照“一般人怎么干这件事”写的，读起来当然顺。真正该问的是另一句：这件事里最容易出问题的地方，它拆进去了吗？大多没有，因为那个地方是你的，不是大多数人的。

我拿一件自己干过几十遍的活试了一次：把一篇写好的技术文章改成十二格漫画。不许动手，只列步骤（图 7-12）。


这八步从确认主题到输出草案，看着完整，却停在分镜草案，没覆盖出图与逐格核字。我在漫画里遇到过“蟹”字出错，才补上这项检查。计划遗漏不能证明训练资料中没有类似经验；能确认的是这次计划没有包含我的验收要求。

规划要有规格与停止条件，把容易出错的步骤明确列入检查。任务范围扩大、约束增多时，计划更需要核对；写进规格也不保证它一定安排到位，要检查实际步骤与交付结果。

**思考**：为什么 Plan-and-Execute 便宜，ReAct 贵？

**参考答案**：ReAct 每走一步都要再问一次大模型，而且每问一次，都得把前面所有来回整个再送一遍，步数一多，账是叠着涨的。Plan-and-Execute 只在开头让大模型想一次，后面照着做，那几步可以交给便宜的模型，或者直接跑工具。

### ReAct：想一步、做一步，看了结果再定下一步

名字是 Reasoning（推理）和 Acting（行动）拼起来的，出自 2022 年普林斯顿大学和谷歌的一篇论文，第一作者姚顺雨。它让模型把“想”和“做”交替着来：想一步，调一次工具，看一眼结果，再想下一步。边想边做，说的就是它。它不是不做计划：论文里“想”那一步本来就要定计划、记进度、改计划，只是计划边做边改，不一次定死。

一圈里的三步各有名字：想那一步叫 **Thought**，动手那一步叫 **Action**，看结果那一步叫 **Observation**（图 7-13）。你去翻它的运行记录，满屏就是这三个词打头的行，认得出这三个，记录就读得懂了。


### 推理与工具结果要相互核对

光想不做，走的就是思维链那条路：步骤全由模型生成，没有一步去外面核对，推错了没人纠正，缺的事实就顺手编一个。反过来，一路调工具却说不清为什么调这个、下一步该干什么，也走不远。

ReAct 把两样接在一起：想的那一步决定去查什么、做什么；做回来的结果，再拿去纠正想法。论文里把答错的例子拆开看，只想不做的那种，一半多错在编了事实；ReAct 答错的那批里，没有一条是编出来的。

它一次拆完的那串步骤，是在什么都还没试过的时候定的。第二步回来的可能是：文件不在那儿、接口换了、数据是空的。一步一看，它就有机会改主意。少了这一眼，就成了闭着眼睛按剧本走：第三步的结果早就不对了，它还照着原计划往下做到第十步（图 7-14）。


**图注**：同一个叉，两条链走出两个结果

两条链上那个叉打在同一个地方，都是第 3 步。上面那条看了一眼，当场拐弯；下面那条没看，一路走到第 10 步才发现。中间那七步不是白走，是白付钱。

看一眼不等于看得懂。它拿到的是一段返回结果，这段结果算成功还是算失败，还是它在猜。返回里写着“查到 0 条”，它可能当成查完了，也可能当成出错了，你得把什么算成功写清楚，它才判得准。

### Agent 循环 agent loop：调模型、跑工具、送回结果

ReAct 讲的是圈里每一步怎么走，这一节讲的是圈本身。边想边做，每一步都是一整圈；先列计划的，列计划那一下是一圈，后面照单执行的步骤要是直接交给代码跑，就不用再转。

外面那层代码把到目前为止的来回送给模型 → 模型回一段字，写着要调哪个工具 → 代码替它跑这个工具 → 把结果接在来回后面，再送给模型。模型回的话里不再要工具，这一圈就是最后一圈。

每一圈它看见的东西都比上一圈多一点。账单涨得比圈数快，原因就在这里。

如果每轮都带上完整历史，第十轮就会再次提供前九轮的内容。实际产品可能筛选、压缩历史或复用缓存，不能只凭循环次数算费用；要查看每轮的输入和计费记录（图 7-16）。


**图注**：圈数一根根加，送出去的量一层层叠

图示假设每圈新增量相同、历史全量重发。十圈累计输入为第一圈的 55 倍；实际用量还要核对工具怎样发送历史，以及缓存计费。

这个圈停在模型觉得干完了的那一刻。它觉得的干完，不一定是你要的；交代出去的那句话里没说清什么算完，它就按自己猜的转下去。

它未必主动跳出循环来问你。除非你事先加了一步停下来等人确认，否则它只要觉得没干完，就一圈一圈转到上限为止，而上限常常是你的额度。

**基础练习**：把任务每次的要求、回答和人工检查结果记下来，找出重复尝试；这不能代替程序调用记录。
