## 7.9　Agent 循环 agent loop：规划、执行并根据结果继续

让AI制作简介时，可以观察它是否读取原文、生成、检查，并根据失败项决定下一步。反复说“再改好一点”却不核对事实，只是在重复，不说明循环有效。

规划说明任务怎样拆，ReAct 说明怎样根据行动结果继续，执行循环说明模型与工具怎样交换请求和结果。下面按这三个层面解释它们怎样配合。

### 规划 planning：模型自己把任务拆成几步

Agent 接到的常常只是一句目标，比如“把这篇文章改成十二格漫画”。从这句话到第一个动作，中间得先想清楚分几步、先做哪一步，这件事叫规划。当时在 OpenAI 的研究员翁荔（Lilian Weng）2023 年写过一篇被引用得很多的文章，把 Agent 拆成四样：大模型，加上规划、记忆、工具使用。后两样这一章各有一节，规划排在最前面。

一种是先规划后执行，英文叫 Plan-and-Execute：先列出步骤，再由执行器完成。执行器可以调用模型或直接使用工具，也可以在遇到变化时重新规划。另一种是边想边做：看了这一步的结果，再决定下一步，ReAct 就采用这种方式。两者都可能多次调用模型，成本要看实际步骤、模型、输入量与返工，不能只凭名称判断。

### ReAct：想一步、做一步，看了结果再定下一步

名字是 Reasoning（推理）和 Acting（行动）拼起来的，出自 2022 年普林斯顿大学和谷歌的一篇论文，第一作者姚顺雨。它让模型把“想”和“做”交替着来：想一步，调一次工具，看一眼结果，再想下一步。边想边做，说的就是它。它不是不做计划：论文里“想”那一步本来就要定计划、记进度、改计划，只是计划边做边改，不一次定死。

一圈里的三步各有名字：想那一步叫 **Thought**，动手那一步叫 **Action**，看结果那一步叫 **Observation**（图 7-14）。你去翻它的运行记录，满屏就是这三个词打头的行，认得出这三个，记录就读得懂了。

> **【图解位　图 7-14】**
> 图注：想、做、看，转完一圈再想
> 画图说明：Cursor 文生图，画风照图 8-3（2026-09-24，任务书 `figs-v3/_new/tasks/fig-7-15.md`，`_内部/refig_cursor.py` 出图、`_内部/换手绘图.py` 换进书）。三个手绘圆角框横排，同一个小机器人：想 Thought（下一步干什么，托着下巴）→ 做 Action（调一次工具，拿扳手）→ 看 Observation（看返回的结果，举放大镜）；底下一条弧线从「看」绕回「想」，标「带着结果再想一步」；「想」左上一支虚线箭头出圈，标「想清楚了就交活」。图上只放标签。原来那版矢量图（`_内部/draw_fig_7_react_loop.py`，同日作者提的：正文说「一圈里的三步」，第 7 章却没有一张图画过这个圈）挪进 `figs-v3/_停用/`。
> 宽度：9.5cm

只生成推导文字而不查外部依据，可能让错误继续传下去；调用工具后，也要判断结果是否足以支持下一步。ReAct 用交替的推理与行动，把外部结果带回后续判断。

ReAct 把两样接在一起：想的那一步决定去查什么、做什么；做回来的结果，再拿去纠正想法。论文在所分析的问答错误样本中，只想不做的那种，一半多错在编了事实；ReAct 答错的那批里，没有一条归入这一类。这是论文当时任务与样本中的结果，不能据此认为 ReAct 消除了幻觉。

它一次拆完的那串步骤，是在什么都还没试过的时候定的。第二步回来的可能是：文件不在那儿、接口换了、数据是空的。一步一看，它就有机会改主意。少了这一眼，就成了闭着眼睛按剧本走：第三步的结果早就不对了，它还照着原计划往下做到第十步（图 7-15）。

> **【图解位　图 7-15】**
>
> **图注**：同一个叉，两条链走出两个结果

两条链上那个叉打在同一个地方，都是第 3 步。上面那条看了一眼，当场拐弯；下面那条没看，一路走到第 10 步才发现。图中未及时处理失败的路径多走了七步。额外用量要查运行记录。

拿到返回结果，还要判断下一步怎么做。例如“查到 0 条”可能是正常的空结果，也可能意味着查错资料库。应写清相应处理条件，再检查模型是否据此继续或停止。

### 执行循环：调模型、跑工具、送回结果

ReAct 讲的是圈里每一步怎么走，这一节讲的是圈本身。边想边做，每一步都是一整圈；先列计划的，列计划那一下是一圈，后面照单执行的步骤要是直接交给代码跑，就不用再转。

一个常见循环是：程序提供任务和已有记录 → 模型提出工具调用 → 程序执行并返回结果 → 模型据此选择下一步。模型给出最终答案，或程序达到停止条件时，循环结束。

以下图示假设每轮都重新发送完整历史。

如果每轮都带上完整历史，第十轮就会再次提供前九轮的内容。实际产品可能筛选、压缩历史或复用缓存，不能只凭循环次数算费用；要查看每轮的输入和计费记录（图 7-17）。

> **【图解位　图 7-17】**
>
> **图注**：圈数一根根加，送出去的量一层层叠

图示假设每圈新增量相同、历史全量重发。十圈累计输入为第一圈的 55 倍；实际用量还要核对工具怎样发送历史，以及缓存计费。

这个圈停在模型觉得干完了的那一刻。它觉得的干完，不一定是你要的；发给 AI 的要求里没说清什么算完成，它就按自己猜的转下去。

不能依赖模型主动停下来询问。需要在指定步骤设置人工确认，并由程序执行次数、时间或用量上限，避免任务一直继续。

查看本次漫画制作中的读取、出图、排字和检查顺序：下一步是否由模型根据返回结果选择，还是照固定程序执行？这能帮助判断用的是Agent循环还是预先安排的工作流。
