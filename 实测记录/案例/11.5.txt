## 11.5　结构化输出 structured output：按固定格式返回结果

结构化输出是按约定字段和类型返回结果，便于程序接着处理。普通聊天工具也可以按要求写出这种结果，但遵守一次格式，不等于接口已启用强制约束。

结构化输出从结果结构、生成约束到接收校验展开。能解析只是起点，内容还要核实。

### 结果结构：约定字段、类型与必填项

> **作者实测**：问答结果与结构化字段
>
> “写过没有”回答“护理假有几天”时，给的是带出处的一句话：“护理假 15 天，须在配偶生育之日起 30 日内一次性休完，逾期不再补休。”这便于人阅读，却没有“天数”和“依据”两个独立字段（图 11-7）。
>
> **【图解位　图 11-7】**
> 图注：带出处的自然语言，仍不是固定字段
> 画图说明：2026-10-02本机新版实际操作重拍。full；选“我的文件”，问“护理假有几天”，仅保留查询区域与完整回答。没有天数、依据两个独立字段。原始截图、页面地址与操作状态保存在本轮截图记录。阶段视图只显示当节已引入的功能，不冒充早期程序存档。
> 宽度：14.2cm
>
> 程序如果要继续处理天数，最好约定字段，而不是每次从变化的句子里提取数字。例如用 JSON 返回：
>
> ```text
> { "天数": 15, "依据": "配偶生育的，享有护理假 15 天" }
> ```
>
> JSON 用字段名与值组织数据。这里“天数”的值是数字，“依据”的值是文字。接收程序可以据此读取和检查；当前网页尚未实现这两个独立字段，不能把示例当成已完成的功能。

### 生成约束：提示要求、JSON 模式与结构约定

只写“请用 JSON 回答”，是对模型的要求；它仍可能附加说明或返回无法解析的文字。支持并正确启用 JSON 模式的接口，约束的是合法 JSON，不保证必填字段齐全或类型符合要求。

接口支持结构约定时，可以进一步规定字段名、类型及必填项。OpenAI 的 Structured Outputs 在支持的模型和调用方式上提供这种约束。受限解码会在生成过程中排除不符合当前结构的候选，例如“天数”约定为数字时，不能在这个位置直接生成“好”（图 11-8）。

> **【图解位　图 11-8】**
>
> **图注**：右半边标 0 的那两个，它想选也选不到
> 画图说明：文生图，画风照图 8-10（2026-09-30）。两边都已经写到 `{ "天数":`。左边「只是叮嘱」，手拿得到「好」。右边「把格式定死」，手拿得到「15」，「好」和「的」被挡住，底下标 0。
> 宽度：11.5cm

这种约束有接口、模型和配置条件，拒绝回答或输出中断也需要单独处理。“格式受约束”不等于数字必然正确，更不等于所有自称兼容的接口都实现了相同机制。

> **作者实测**：JSON 开关与实际返回
>
> 我在另一家接口上分别做了 20 个新对话。只在提示词里要求“请只回 JSON”，8 次整段是合法 JSON；打开接口的 JSON 开关、去掉这句要求后，再试 20 次，9 次合法。合法结果中的数字都正确；其余结果仍是带出处的自然语言，没有按要求返回 JSON。
>
> 这说明当时的接口收下了该配置，却没有达到每次返回合法 JSON 的要求。不能凭“没有报错”确认功能生效，也不能用这个样本推断所有 JSON 模式的表现。应核对接口支持范围、实际请求和响应，再检查接收端是否阻止不合格结果继续处理。

### 接收校验：结构合格之后还要查内容

**格式。**检查 JSON 是否能解析，必填字段是否齐全，“天数”是否为数字、“依据”是否为文字。不符合约定的结果应停止进入后续写入。

**出处。**把“依据”拿回原文核对，不仅要找到这句话，还要确认它说的是护理假，而不是其他假期。

**事实。**再核对天数是否符合有效制度；若是计算结果，另用代码或手算复核。三项检查针对不同错误（图 11-9）；无法核对的字段要标为未验证。

**思考**：除了 JSON，你再查查还有哪些常见的输出结构？

**参考答案**：常见的还有 CSV、XML 和 YAML。CSV 用行和列组织表格数据；XML 用标签标明内容及层级；YAML 常用缩进表示层级。选择哪种格式，要看结果给谁读取、后续程序支持什么。
