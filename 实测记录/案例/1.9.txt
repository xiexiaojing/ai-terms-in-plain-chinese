## 1.9　模型即服务 MaaS：通过 API 使用模型，不必自己部署和维护

MaaS 是 Model as a Service 的缩写，中文叫模型即服务。服务商负责部署和运行模型，你的程序通过 API 发送请求、取得结果，不必自己准备运行模型的服务器，也不必自己维护模型服务。

前一节的开放平台是获取接口、密钥和查看用量的入口；MaaS 说的是模型如何提供给你使用。你从开放平台拿到 API key，把模型接进自己的系统，就是通过服务使用模型。平台也可能提供其他功能，不能把整个平台都等同于 MaaS。

> **进阶阅读**：将模型服务接入自己的程序
>
> 使用 MaaS 时，模型运行交给服务商；资料、调用方式和结果仍由使用者安排。
>
> ### 服务分工：厂商运行模型，使用者调用接口
>
> 调用模型服务时，模型运行在服务商的服务器上，你的程序发送请求、接收结果。如果想在自己的电脑上运行，还要确认服务商是否提供模型下载，以及需要什么硬件和软件。即使同一个模型同时支持这两种方式，通过接口调用和下载后自己运行，也要分别准备。
>
> ### 接入准备：资料外发、费用与失败处理
>
> 哪些资料可以发送给服务商，要按资料权限和服务的数据处理规则判断；用了多少、怎样计费，要看调用记录和账单；服务暂时不可用时怎么办，要预先准备降级等处理办法。

**进阶验证**：打开一个模型的 API 文档，记录模型名称、支持的输入输出、计费单位与限制。再查看账号权益，确认聊天订阅是否包含 API 额度。此处先读说明，不必编程或发起付费调用。
