## 7.6　图形用户界面智能体 GUI Agent：自动看屏幕做操作

GUI 是 graphical user interface 的缩写，平时说得多的是 GUI 智能体。它在界面上一步一步把事办完：点哪儿、填什么、下一步干什么，都是它现场定的，不是事先写好的。

> **作者亲历**：举起双手，老板才看明白是 AI 在操作
>
> 2026 年初，我们的产品从点按钮的界面往跟 AI 对话的界面转，做了一个 AI 助理。我作为驻场工程师去客户现场演示：从别的平台复制一条姓名、地址、手机号，到我们平台粘贴，后面跟一句指令：下单。回车，单就下好了（图 7-6）。
>

> 图注：粘贴一条姓名地址手机号，跟一句“下单”
> 画图说明：`_内部/compose_chat3.py 7-9` 画的对话框（字在 `figs-v3/_文生图对话框-20260917/content.json` 的 7-9）。演示时屏幕上只有这个对话框：右边用户气泡，三行粘贴进来的示例信息（姓名：长腿蟹／地址：小胖蟹的上铺／手机号：188 0000 0000），末行加粗「下单」；左边机器人回「下单成功。」。全是示例信息，没有真人。**宽度按对话框图的统一字号算**：画布 880 宽，别的对话框图是 1700 宽排 12.5cm，这张原来排 11cm，字大了七成（2026-09-24 作者看出来的）。

>
> 演示完，两个问题。第一个，慢。背后实际做了很多操作，用户在那儿等。
>
> 第二个更重要：客户不放心。“下单成功”的通知他们是收到了，可还是要去订单列表里点开看一眼：下单内容对不对，地址对不对。助理告诉他“成了”，他要的是亲眼看见怎么成的。我想了一个办法：换 GUI Agent。填地址、下单这几步不调接口了，调我们原来的界面，让它像人一样在页面上操作：打开下单页，一个框一个框地填，最后点提交（图 7-7）。
>
> **【图解位　图 7-7】**
> 图注：同一个下单页，它一个框一个框地填
> 画图说明：Cursor 文生图手绘版（任务书 `figs-v3/_new/tasks/fig-7-8-gui-order.md`，`_内部/refig_cursor.py` 出图、`_内部/换手绘图.py 7-9` 换进来；2026-09-26 作者嫌原矢量图丑，原图和 `draw_fig_7_gui_order.py` 的输出都进了 `_停用/`）。同一个下单页三格，箭头相连，同一个小机器人在旁边操作：① 打开下单页（三个空框和「提交」）② 一个框一个框地填（姓名已填，地址正在填、框加粗带光标，手机号还空着）③ 点提交（三格都填好，「提交」涂黑，鼠标指针落在上面）。示例信息跟图 7-6 那条一样。图上只放标签。
> 宽度：12.5cm
>
> 用户全程看着字一个个填进原来那些框里，看得见，就放心了。接口那条路快而看不见，界面这条路慢而看得见，客户这一次要的是后者。
>
> 用了一天做出个演示版本，去给老板演示。第一遍老板没看明白：屏幕上的框一个接一个被填上，他以为是我自己在飞快地点鼠标。
>
> 旁边同事提醒我：把内容输进去以后，你把手举起来。我照做，又演示了一遍：粘贴完那段话，按下回车，我举起双手：“我什么都没有做！”这一次老板看明白了。

回头看，这次演示教了我两件事。客户需要看见操作过程，因此我选择在他们熟悉的界面上演示。实际执行时，还要看任务、接口条件和维护成本，不能仅凭有没有人观看来选。还有，自动操作看着越像有人在操作，演示时越要证明那只手不是我的。

GUI Agent 涉及操作路线、界面识别和执行核对。三者分别说明怎样操作、看见什么、是否做对。

### 操作路线：接口、固定脚本与 GUI Agent

**接口**：应用把功能直接开放给程序调，不经过界面。有合适接口时，通常优先考虑直接调用；仍要检查权限、稳定性和返回结果。公司里那套用了十年的老系统、不开放的网站，人能点，程序进不去，可以考虑界面操作，或先确认有没有导入导出等入口。同一个助手里两条路常常都在用：能直接调的走接口，调不了的才去点界面。

**写死的点击脚本**：也在点界面，但点哪儿、等几秒、按什么顺序，全是人事先写好的。我有一个往公众号草稿箱自动填稿的脚本，从登录到传十二张图再到保存，全程都在点界面，可点哪个按钮、等几秒、标题得用键盘敲不能粘贴，每一条都是我踩出来、一行一行写死的。后台改一个按钮位置，它就停在那儿报错，不会自己去找。

分界在于**下一步由谁决定**。脚本照着写好的走，GUI Agent 看着屏幕现场定（图 7-8）。

> **图注**：上面那一排在不在，就是分界

点击脚本通常按预设步骤和定位规则执行；GUI Agent 可以读取页面状态，再决定下一步。我让助手在“写过没有”上选资料范围、输入问题、发送并核对答案，图 7-9 保留了这次实际操作的五个状态。

网页上有个“画漫画”按钮，点后由后台调用模型，这属于应用使用 AI；GUI Agent 则是 AI 自己操作界面，点击按钮、填写内容。

### 界面识别：截图与元素结构

一种路线把截图交给模型识别按钮与文字；另一种读取网页结构或系统无障碍树。截图可能识别错误，结构也可能缺失、过期或与视觉界面不符。选择哪种路线，要看实际可取得的信息与操作成功率，有的产品会组合使用。

### 执行核对：操作结果、用量与权限

界面操作可能需要多次识别与模型调用，耗时和费用要与可用接口方案实际比较。它是看着屏幕猜下一步，猜错了点下去，那一下是真的点了。所以这类东西第一件事是划清它能碰哪些页面；动钱、往外发东西的那几步，留给人点头。

一件事你每周都要干一遍、界面又不常变，固定脚本可能减少重复判断，但还要计算编写与维护成本。

**思考**：客服交回一张发票，能据此确认它是通过看屏幕、点按钮开出来的吗？

**参考答案**：不能。它也可能调用接口或固定程序。要判断是不是GUI Agent，需要实际操作记录，显示它怎样识别界面并操作。
