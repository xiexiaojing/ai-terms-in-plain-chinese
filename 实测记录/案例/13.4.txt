## 13.4　编排 orchestration：安排多个 Agent 的先后和分工

编排规定谁做什么、谁先执行、怎样交接、失败后怎么办。常见安排有顺序执行、主 Agent 协调、并行处理后汇总（图 13-6）。主 Agent 也可以自己执行任务，不必只负责指挥。

批量制作漫画时，可以把制作和核验分给不同角色：制作方交出图与文案，核验方拿原故事、规格和成品逐项检查，负责人决定是否发布。未通过就返回制作方，不能只传一句“检查过了”。

> **补充说明**
>
> “编排”这个词在汉语里本来的意思是“依次排列”，另一个意思是“捏造话讥诮别人”。这里取“依次排列”的含义。

斯坦福和谷歌 2023 年那篇《Generative Agents》试过一次。他们在一个虚拟小镇里放了 25 个 Agent，各有各的身份、住处和日程，见了面能搭话。研究者只对其中一个说了一句：你想办个情人节派对。

剩下的没有人安排。两天里这件事靠它们互相传，从 1 个人知道变成 13 个人知道，中间还有约了伴一起去的。

派对当天，被邀请的 12 个到场 5 个。没到的 7 个里，3 个另有安排（有个画家在忙自己的画展），4 个之前说想去、当天没去。

传开了是真的，办成了一半也是真的。25 个 Agent 各自记着自己的事，没有谁负责点名。

编排还应规定结果冲突时怎样复核、由谁决定。只安排执行顺序，不能解决两个Agent给出相反结论的问题。

我那一次的顺序是：主 Agent 先派甲、再派乙，两个同时跑，主 Agent 干等；甲乙各自回来，主 Agent 才开始汇总。先后和分工都是主 Agent 定的，子 Agent 不知道彼此存在。换成流水线就不一样了：比如出这本书合订本的五道工序，先后是写死的，谁也不用等谁“决定”。
